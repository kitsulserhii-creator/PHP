# Лабораторна робота №5: Авторизація користувачів

## Виконані завдання ✅

### 1. Поле admin в таблиці users (1 бал)
- **Тип**: `TINYINT(1)` (boolean)
- **Значення**: `1` для адміністраторів, `0` для звичайних користувачів
- **За замовчуванням**: `0` (нові користувачі - звичайні)
- **Створено в**: Лабораторній роботі №4 (вже присутнє в схемі)

### 2. Форма авторизації login.php (1 бал)
- Створено форму входу в `layout/views/login.php`
- Поля:
  - Логін (текстове поле, обов'язкове)
  - Пароль (password type, обов'язкове)
  - CSRF токен (прихований)
- Перевірка користувача через базу даних з підготовленими запитами
- Використання `password_verify()` для перевірки паролів
- Однакове повідомлення про помилку для запобігання enumeration attacks

### 3. Перевірка логіну/паролю з password_verify (2 бали)
- При успішному вході:
  - `session_regenerate_id(true)` - захист від session fixation
  - Збереження `user_id`, `user_logged`, `user_admin` в сесії
  - Перенаправлення на профіль
- При помилці:
  - Загальне повідомлення "Неправильний логін або пароль"
  - Логування помилок без розголошення деталей користувачу

### 4. Додавання двох нових пунктів меню (2 бали)

**Для неавторизованих користувачів (гостей)**:
- ✅ "Увійти" - посилання на сторінку входу
- ✅ "Реєстрація" - посилання на форму реєстрації

**Для авторизованих користувачів**:
- ✅ "Профіль" - перегляд особистого профілю
- ✅ "Вийти" - вихід з системи

**Для адміністраторів**:
- ✅ Окрема секція "АДМІН" в меню (підготовка для CRUD операцій)

## Додаткові реалізовані функції 🚀

### CSRF захист (не в завданні, але критично важливо)
- Генерація криптографічно безпечного токена: `bin2hex(random_bytes(32))`
- Перевірка токена через `hash_equals()` (захист від timing attacks)
- Токен зберігається в сесії та передається через приховане поле форми
- Регенерація токена після успішної авторизації
- Всі POST форми (login, registration) захищені CSRF токеном

### Безпечні HTTP заголовки
Додано до `layout/header.php`:
```php
X-Content-Type-Options: nosniff          // Захист від MIME type sniffing
X-Frame-Options: DENY                     // Захист від clickjacking
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), microphone=(), camera=()
Content-Security-Policy: ...              // Захист від XSS
```

### Безпечна конфігурація сесій
```php
session.cookie_httponly = 1               // Захист від XSS атак на cookies
session.cookie_samesite = Strict          // Захист від CSRF
session.cookie_secure = 1                 // Тільки HTTPS (якщо доступно)
session_regenerate_id(true)               // Після логіну та зміни привілеїв
```

### Інтеграція з базою даних
- Всі форми (login, registration, profile) працюють з БД через PDO
- Захист від SQL ін'єкцій через підготовлені запити
- Валідація даних на стороні сервера перед записом
- Безпечна обробка помилок (не розголошують структуру БД)

### Output Escaping
- Всі виведення користувацьких даних через `htmlspecialchars()`
- Параметри: `ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8'`
- Захист від XSS атак

## Як протестувати

Переконайтесь, що виконано Лабораторну №4 і база даних `phpp_portfolio` створена.

### Крок 2: Тестові облікові записи

- Логін: `admin`
- Пароль: `Password123`

**Звичайний користувач**:
- Логін: `user1`
- Пароль: `Password123`

### Крок 3: Перевірка функціоналу

1. **Вхід**:
   - Перейти на http://localhost/phpp/index.php?action=login
   - Ввести логін `admin` та пароль `Password123`
   - Має відкритись профіль з позначкою "Адміністратор"

2. **Реєстрація**:
   - Перейти на http://localhost/phpp/index.php?action=registration
   - Заповнити всі поля
   - Після успішної реєстрації - автоматичний вхід

3. **Перевірка меню**:
   - Гість бачить: "Головна", "Про сайт", "Реєстрація", "Увійти"
   - Користувач бачить: "Головна", "Про сайт", "Профіль", "Вийти"
   - Адмін бачить: те саме + секція "АДМІН"

4. **CSRF захист**:
   - Спробувати відправити форму без токена - відхилиться
   - Спробувати змінити токен - відхилиться

5. **Вихід**:
   - Натиснути "Вийти" - сесія очищається, перенаправлення на головну

## Безпека - реалізовано в повному обсязі

### Захист від атак:
1. ✅ **SQL Injection** - PDO підготовлені запити, `EMULATE_PREPARES=false`
2. ✅ **XSS** - `htmlspecialchars()` на всіх виведеннях + CSP заголовки
3. ✅ **CSRF** - Токени на всіх POST формах
4. ✅ **Session Fixation** - `session_regenerate_id(true)` після логіну
5. ✅ **Clickjacking** - `X-Frame-Options: DENY`
6. ✅ **MIME Sniffing** - `X-Content-Type-Options: nosniff`
7. ✅ **Username Enumeration** - Однакові повідомлення про помилки
8. ✅ **Timing Attacks** - `hash_equals()` для порівняння токенів

### Безпека паролів:
- `PASSWORD_BCRYPT` з cost factor 12
- Паролі ніколи не зберігаються в plain text
- Перевірка через `password_verify()`

### Валідація даних:
- Всі поля форм валідуються на сервері
- Типізація через `(int)`, `trim()`, регулярні вирази
- Whitelist підхід - приймаємо тільки відомі безпечні значення
